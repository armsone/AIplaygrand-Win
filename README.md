# AIplaygrand-Win · USB 에디션

Claude 2명과 Gemini 1명으로 시작하는 초보 팀의 AI 실습 공간입니다. Codex를 포함해 팀원을 추가할 수 있습니다. API 키 없이 공식 웹사이트 또는 설치된 공식 CLI를 열고, 사람이 질문을 직접 전송하거나 옵트인 자동 전송으로 답변을 기록합니다. 설치된 공식 CLI로 **자동 3단계 팀 릴레이** 및 **1:1 앱 내 CLI 대화(공용 CLI 또는 팀원별 독립 CLI 자리)**를 실행할 수 있습니다.

## 빠른 시작 (초보자 안내 · Quick Start)

1. **준비 및 실행**: Windows x64 ZIP **전체**를 쓰기 가능한 USB 폴더에 풀고 `AIplaygrand-Win.exe`를 실행합니다 (`exe`만 단독 이동 금지, 실행 파일 옆 `Data` 폴더와 항상 함께 보관).
2. **보관함 열기**: 마스터 비밀번호를 설정/입력하여 잠금을 해제합니다. 빈 값과 공백을 포함해 길이·문자 조합 규칙은 없으며, 비밀번호 분실 시 복구할 수 없습니다.
3. **팀원 로그인**:
   - 웹 팀원: **우리 팀**에서 **열기** 클릭 → **로그인 전 설정** 확인 후 **저장하고 웹창 열기** → 열린 전용 브라우저에서 공식 로그인.
   - 독립 CLI 자리: **팀원 추가**에서 '독립 CLI 자리'를 만들고 **로그인 터미널** 클릭 → 설정 확인 후 **저장하고 로그인 터미널 열기** → 열린 공식 터미널에서 로그인 완료 후 **로그인 상태**로 점검 (필요 시 '로그인 보관'으로 보관함에 백업).
4. **미션 작성과 실행**:
   - 질문 작성란에 내용을 적고, **이번 차례**와 **실행 방식**을 선택한 뒤 **미션 추가**를 누릅니다.
   - 실습 기록 카드에서 실행:
     - 웹 브라우저: **질문 복사하고 [서비스] 웹 열기** → 전용 창에 붙여넣어 직접 전송.
     - 웹 자동 전송: **자동 전송으로 실행** (Claude·Gemini 웹 지원, 보이는 웹창에서 1회 전송·관찰).
     - CLI 대화: **질문을 [이름] 독립 자리 대화에 넣기** 또는 **공용 CLI 대화에 넣기** → 대화창에서 검토 후 전송.
     - CLI 터미널: **질문 복사하고 [서비스] 공용 터미널 열기** → 터미널에서 직접 실행.
5. **한도 도달 시 인계**:
   - 수동 인계: **사용량 소진 · 다음 팀원에게** 클릭 (질문 복사 및 다음 웹창 열기).
   - 자동 이어받기: **사용량 소진 · 자동 이어받기** 클릭 또는 구조화 한도 감지 시 (보내는 팀원과 받는 팀원 모두 자동 전송·부분 답변 공유에 동의 시 5초 취소 타이머 후 자동 전송, 미확인 오류는 멈춤).
6. **답변 정리와 완료**:
   - AI 답변과 배운 점을 정리하고 **실습 기록 저장**을 눌러 완료합니다. (결과물은 AI 텍스트 답변·코드 제안이며 실행 파일 자동 생성이 아닙니다.)
7. **안전한 이동 순서**:
   - 상단 **저장하고 종료** 클릭 → 별도로 열린 모든 CLI 터미널 닫기 → Windows **하드웨어 안전하게 제거** → `Data` 폴더를 포함한 **폴더 전체**를 새 PC로 복사/이동 → 새 PC에서 CLI 환경 확인 및 로그인 (독립 자리는 '로그인 복원' 활용 가능).

## 웹 팀원 이어받기 (수동 핸드오프)

- **사전 동의와 보관함 저장**: 각 팀원은 로그인 설정에서 이어받기 수신을 명시적으로 동의(기본값 꺼짐)한 경우에만 5초 뒤 자동 인계 창 열기가 적용됩니다. 동의하지 않은 팀원도 직접 이어받을 수 있습니다. 프로필별 동의 여부는 `Data/team.vault`에 암호화 저장되며 프로필 버튼에서 언제든 수정·철회할 수 있습니다.
- **수동 소진 표시와 후보 목록**: 이 수동 경로에서는 앱이 쿼터(사용량 한도)를 자동 감지하지 않습니다. 사람이 직접 소진을 표시하면 원래 팀원은 일시중단되고 작성 중이던 부분 답변은 보존됩니다. 이번 앱 세션의 후보 목록에서 소진 표시된 프로필은 제외되며, '다시 참여'를 눌러 명시적으로 복귀시킬 수 있습니다(실제 쿼터 검증 아님). 모든 후보의 로그인 여부와 남은 사용량은 소유자가 직접 확인할 때까지 알 수 없습니다.
- **5초 타이머와 창 열기**: 동의된 대상 선택 시 5초 취소 카운트다운 타이머가 표시되며, 다른 후보를 선택하면 타이머가 초기화되고 미동의 대상은 '이어받기'을 직접 눌러 진행합니다. 취소·포커스 해제(blur)·새로고침·종료 시 카운트다운이 취소됩니다.
- **저장과 수동 전송**: 대기열의 새 미션이 먼저 저장된 후 클립보드 복사와 전용 웹 창 열기가 진행됩니다. 이 기본 수동 경로에서는 제공자 사이트로의 자동 전송이나 CLI 계정 전환을 하지 않으며, 자동 전송과 독립 CLI 자리는 아래 별도 옵트인 기능을 통해서만 동작합니다.

## 자동 이어받기 · 웹 자동 전송 · 독립 CLI 자리 (옵트인, 실기기 미검증)

위 수동 핸드오프(복사·창 열기)는 그대로 남아 있고, 그 위에 **사용량 소진 → 다음 동의 팀원 → 5초 취소 타이머 → 자동 전송·관찰**이 추가되었습니다. 구현 파일은 `web-auto.js`(웹 자동 전송), `auto-handoff.js`(통합 자동 인계), `cli-seats.js`(독립 CLI 자리)이며 판단·타이머·동의 확인·저장은 모두 메인 프로세스가 담당합니다.

- **새 동의(v2)만 자동 전송을 허용합니다.** 팀원 카드의 ‘자동 인계 설정’(또는 ‘열기’ 전 설정)에서 ‘자동으로 전송’과 ‘다른 팀원의 부분 답변 공유’를 **둘 다** 체크해야 `autoContinueConsent {version:2, autoSend, shareContext}`가 보관함에 저장됩니다. 기존 복사·열기 동의(`autoHandoffConsent`)는 별개 항목이며 자동으로 승격되지 않습니다. 하나라도 끄면 필드가 삭제되어 즉시 후보에서 빠집니다. **원래 담당(소스) 쪽 동의도 필요합니다.** 한도가 감지됐을 때 자동으로 타이머가 시작되는 것은 소스 팀원(웹 프로필 또는 독립 CLI 자리)에 같은 v2 동의가 있을 때뿐이고, 공용 CLI(이 PC 로그인 계정)는 CLI 대화 화면의 별도 설정으로만 동의합니다. 소스 동의가 없으면 세션은 ‘멈춤’으로 표시되어 ‘지금 이어받기’를 눌러야만 부분 답변이 넘어갑니다. 미션 시작 클릭이나 자리(seat) 보유는 동의로 치지 않습니다.
- **시작 조건.** (1) 실습 기록의 ‘사용량 소진 · 자동 이어받기’(사람이 직접 표시, 누를 때 부분 답변 공유를 확인), (2) 웹 자동 전송 중 해당 서비스의 **전용 오류 배너**(대화 메시지 바깥)가 새 대화 화면·전송 직후 15초·관찰 중에 새로 나타나고 문구가 ‘사용량/메시지 한도 도달’류의 명시적 소진 표현일 때(‘limit’·‘quota’ 단독, 429, too many requests, 네트워크·컨텍스트 길이 문구는 제외), (3) CLI 대화가 **공식 구조화 이벤트**로 한도를 보고할 때. CLI별 지원: **Claude Code**는 `rate_limit_event`의 `rate_limit_info.status === "rejected"`이면서 창(`rateLimitType`)이 `five_hour`/`seven_day`/`seven_day_opus`/`seven_day_sonnet`일 때만(overage 거부는 소진 아님), **Gemini CLI 0.59.0**은 `result.error.type === "TerminalQuotaError"`(비재시도 한도 차단, 일일 한도가 아닐 수도 있음)일 때만이며 `RetryableQuotaError`(일시 제한)는 넘기지 않습니다. **Codex CLI**는 공식 프로토콜(`UsageLimitReachedError` Display)에 따라 터미널 JSON의 `turn.failed.error.message`(또는 최상위 `type: "error"`)가 일반 계정 사용량 한도 접두사 `"You’ve hit your usage limit."`로 시작할 때만 한도로 인정합니다(모델별 한도인 "... for <model>", 크레딧/워크스페이스 결제 한도, 어시스턴트 본문, item 텍스트, stderr, 429는 수동 유지). 그 외의 모든 Codex 오류는 ‘확인 안 됨’으로 멈추고 수동으로만 넘깁니다(독립 자리와 Codex CLI로 이어받는 것은 가능). 답변 본문·일반 오류 문구·HTTP 429·네트워크 오류는 한도로 보지 않으며, 한도가 확인되지 않은 오류는 화면에 멈춤으로 표시하고 자동으로 넘기지 않습니다. 공용 CLI는 팀원 이름으로 표시되지 않습니다.
- **후보와 타이머.** 후보는 원래 담당 다음 순서부터 ‘v2 동의 + 사용량 소진 미표시 + 이번 연쇄에서 미사용 + (웹은 자동 전송 지원 서비스, 또는 독립 CLI 자리)’인 팀원이며, 화면에는 **‘동의 설정됨 · 로그인 확인 필요 · 남은 사용량 알 수 없음’**으로 표시됩니다(사용 가능 보장이 아님). 5초 타이머는 앱 메인 창이 화면 앞에 있을 때만 흐릅니다. 이 앱의 웹창을 보고 있을 때 한도가 감지되면 메인 창을 앞으로 가져온 뒤 시작하고, 앱이 뒤에 있으면 포커스를 빼앗지 않고 멈춘 채 기다립니다. 취소·건너뛰기·팀원 변경은 언제나 가능하고, 실행 직전에 보관함을 다시 읽어 동의·소진 여부를 재확인하며, 웹 클릭·CLI 실행 직전에 백엔드가 세대(generation)·상태·동의·팀원 정체(삭제·서비스 변경·동의 철회)를 한 번 더 확인합니다. 취소는 타이머뿐 아니라 준비 중인 전송(실행 전이면 아무것도 보내지 않음)과 이 세션이 시작한 실행(다른 수동 실행은 건드리지 않음)을 함께 멈춥니다. 같은 팀원을 반복하거나 자동 재시도하지 않으며 실패하면 다음 후보를 제안만 합니다(자동 시작 아님).
- **웹 자동 전송(Claude 웹·Gemini 웹).** 팀원의 앱 전용 격리 웹창(보이는 창)에서 진행합니다. 허용 origin(`https://claude.ai`, `https://gemini.google.com`)과 로그인·결제 경로 제외를 메인에서 매 스크립트 실행 전에 확인하고 스크립트 안에서도 origin과 경로를 다시 확인합니다. **계정 표식**(사용자 메뉴 등)이 보여야 로그인으로 인정하며 쿠키·작성창·로그인 버튼 부재는 증거로 쓰지 않습니다. 입력창에 사용자의 글이 있으면 덮어쓰지 않고 멈춥니다. 전송은 버튼 클릭 1회이며 클릭 전에 ‘전송 시도’를 보관함에 먼저 기록하고 페이지 안에서도 전송 플래그를 선점해 재클릭·Enter·폼 제출 대체가 없습니다. 클릭 결과를 확인하지 못한 채 취소·창 닫힘이 일어나면 ‘실제 전송 여부 미확인’으로 표시하고 다시 보내지 않습니다. 전송 직후 15초 동안 전용 배너를 먼저 분류하고(한도 → 소진 확인, 그 외 → 한도 미확인 오류), 배너가 없을 때 새 답변 노드 또는 **같은 노드의 내용 변화**(전송 전 마지막 답변의 노드 수·본문을 기준선으로 비교)나 생성 표시가 있어야 접수로 봅니다. 이후 최대 119초(화면에 역카운터와 진행 바) 동안 관찰해 생성 표시가 없고 같은 비어 있지 않은 답변(코드 블록을 포함한 전체 본문)이 3회 연속 읽히면 완료합니다. 부분 답변은 관찰 중 2.5초 간격으로 보관함(`webRuns`)에 암호화 저장되고 취소·오류 시에도 보존되어 해당 미션 답변란에 들어갑니다. **저장은 fail-closed입니다.** 시작 기록 저장에 실패하면 시작하지 않고, 마지막 저장에 실패하면 결과를 화면에 그대로 남긴 채 ‘저장 실패’로 표시하고 ‘저장 다시 시도’가 성공할 때까지 다른 팀원에게 넘기지 않으며 새 실행도 시작하지 않습니다(CLI 대화·릴레이도 동일). 질문·답변은 로그에 남기지 않습니다.
- **Codex 웹은 자동 전송을 지원하지 않습니다.** https://chatgpt.com/codex/cloud 작업 화면의 코드 환경 설정과 입력·실행·결과 연결 확인 전에는 수동 사용을 유지하며, 수동 열기와 클립보드 복사만 제공합니다. 일반 ChatGPT 대화 화면으로 대체하거나 임의 셀렉터를 사용하지 않으며, 클라우드 수동 작업과 공식 CLI 자동 실행은 명확히 구분됩니다.
- **독립 CLI 자리 및 로그인 보관·복원·삭제.** 팀원 추가에서 ‘독립 CLI 자리’를 고르면 OS 앱 데이터 폴더 아래 `AIplaygrand-Win/CliSeats/<서비스>/<프로필 id>/`가 그 팀원 전용 CLI 설정 폴더가 됩니다. Claude Code는 `CLAUDE_CONFIG_DIR`, Codex CLI는 `CODEX_HOME` + `-c cli_auth_credentials_store="file"`(문서화된 파일 저장 방식, 키체인 방식은 자리별 격리가 문서화되지 않아 사용하지 않음), Gemini CLI는 `GEMINI_CLI_HOME`(기존 앱 전용 런타임과 동일 정책)을 사용합니다. ‘로그인 터미널’은 이 환경으로 공식 로그인 명령(`claude auth login`, `codex login`, `gemini`)을 열고 팀원이 직접 로그인합니다. ‘로그인 상태’는 공식 상태 명령(`claude auth status --json`, `codex login status`)의 종료 코드·불리언만 해석하며 자격 증명 파일은 읽지 않습니다. Gemini에는 상태 명령이 없어 ‘확인 불가’로 표시합니다. 로그인·상태·자동 실행 모두 같은 allowlist 환경(API 키·토큰·공급자 override 제외)을 받으며 기존 도구 차단·샌드박스·MCP 차단 옵션은 그대로입니다. CLI 대화 화면의 ‘CLI 계정 자리’에서 공용 CLI 또는 독립 자리를 고를 수 있습니다.
  - **명시적 로그인 보관·복원·삭제 제어**: 독립 CLI 자리는 앱이 소유한 독립 자리 전용 제어로 '로그인 보관', '로그인 복원', '보관된 로그인 삭제'를 제공합니다. 캡처 대상은 공식 CLI 저장소 규격에 따라 Codex `CODEX_HOME/auth.json`(ChatGPT 토큰), Gemini `GEMINI_CLI_HOME/.gemini/oauth_creds.json`(OAuth 자격증명), Claude Windows/Linux `CLAUDE_CONFIG_DIR/.credentials.json`에 엄격히 한정됩니다([learn.chatgpt.com/docs/auth](https://learn.chatgpt.com/docs/auth), [code.claude.com/docs/en/team](https://code.claude.com/docs/en/team), [github.com/google-gemini/gemini-cli/blob/v0.59.0/packages/core/src/config/storage.ts](https://github.com/google-gemini/gemini-cli/blob/v0.59.0/packages/core/src/config/storage.ts) 참고). Mac Claude Keychain 이동은 지원되지 않으며, OS 전역 키체인이나 타 앱 비밀정보는 일절 가져오지 않습니다. 보관된 토큰은 비밀번호로 암호화된 `Data/team.vault`에 저장됩니다. 복원은 비어 있는 동일 자리 PC 자격 증명 경로로만 수행되며 기존 로그인을 절대 덮어쓰지 않습니다. 모든 보관·복원·삭제는 매 실행 전 사용자의 명시적 확인을 거치며, 로그인 캡처(보관) 전 열려 있는 모든 CLI 터미널을 반드시 닫아야 합니다. 저장된 토큰은 만료되거나 회전될 수 있으므로 PC 이동 전 백업을 갱신하고 단일 활성 PC 유지를 권장하며, 공식 재로그인이 필요할 수 있습니다. 복원된 PC 파일은 운영체제 사용자 권한을 따르는 공식 CLI 평문 저장소이므로 앱 보관함 암호화가 로컬 PC 사본을 보호하지 않습니다(보관함 `.bak`에 삭제된 복사본이 남을 수 있음). 브라우저 쿠키 복원은 기존과 같이 최선 노력(best-effort)으로 유지됩니다.
- **지원 범위와 검증되지 않은 부분.** 구현된 경로: 웹 자동 전송(Claude 웹·Gemini 웹), 웹→웹/CLI 자리, CLI 자리→웹/CLI 자리, 공용 CLI→웹/CLI 자리 이어받기, Claude Code·Gemini CLI·Codex CLI의 구조화 한도 이벤트 감지, 3단계 릴레이 도중 확인된 쿼터 소진 시 동일 제공자 후보 CLI 자리로의 5초 취소 카운트다운 자동 이어받기(별도 릴레이 자동 인계 동의와 소스·후보 자리의 v2 동의 시) 및 동일 제공자 독립 자리 수동 인계. 지원하지 않는 것: 웹과 3단계 릴레이 간의 자동 핸드오프(3단계 릴레이는 동일 제공자 CLI 간으로만 한정), 3단계 릴레이 초기 단계별 자리 선택자(초기는 쿼터 소진 전까지 공용 CLI 고정), 앱 시작 및 새로고침 시 자동 재개, Codex 웹 자동 전송(클라우드 작업 환경 사전 확인 필요로 수동 유지), Codex 모델별 한도 및 결제 한도 자동 감지, 미확인 오류나 인증 실패 시의 자동 재시도 루프. 실제 사이트 DOM(셀렉터는 AIBI 참조 런타임에서 가져옴)과 한도 배너 문구, Claude Code가 `-p` 스트림에서 `rate_limit_event`를 실제로 내보내는지, Claude/Codex 상태 명령의 출력 형식, 각 CLI의 자리별 격리 동작은 실기기·실계정·라이브 DOM으로 확인하지 않았습니다. 계정 로그인 상태와 남은 사용량은 사전 검증되지 않은 채(후보 자리는 설정된 자리일 뿐 로그인 여부나 쿼터가 검증된 상태가 아님) 프로필별 v2 명시적 동의와 전면 5초 취소 카운트다운(‘로그인·남은 사용량은 확인되지 않았어요’ 고지)을 거쳐 자동 인계가 진행되며, 화면 포커스 해제 시 카운트다운이 일시정지되고 후보 선택·건너뛰기·취소가 가능합니다. 명시적인 한도 소진이 확인된 경우에만 다음 자동 이어받기가 지속되고 알 수 없는 오류나 인증 오류는 첫 요청 전송 이후 발생하더라도 추가 자동 인계를 즉시 중단합니다(재시도 루프 없음).

## CLI 팀 릴레이

작업 하나를 적으면 세 단계가 순서대로 실행됩니다. 기본 구성은 Claude → Gemini → Claude이며 단계마다 공급자와 역할 설명을 바꿀 수 있습니다. 각 단계는 원래 요청과 앞선 단계의 완료 결과를 함께 받습니다. **Claude Code·Codex CLI·Gemini CLI를 앱 내 대화와 릴레이에 연결합니다.** 각 CLI 설치와 별도의 서비스 이용 권한이 필요합니다.

- **3단계 팀 릴레이는 공용 CLI 비대화형 실행을 기본으로 하며, 확인된 쿼터 소진 시 동일 제공자 후보 CLI 자리로의 5초 자동 이어받기 및 명시적 수동 이어받기를 지원합니다.** 3단계 릴레이는 쿼터 도달 전까지 공용 CLI로 실행되며(초기 단계별 자리 선택자는 추가되지 않음), 실행 중 확인된 쿼터 소진(`confirmed quota failure`) 발생 시 별도 릴레이 자동 인계 스위치(기본 꺼짐)와 소스 독립 자리의 v2 옵트인(`autoSend` 및 `shareContext`) 및 동일 제공자(same-provider) 후보 CLI 자리의 v2 동의(`autoContinueConsent`)가 충족되면 화면에 보이는 5초 취소 카운트다운 타이머 후 실패한 단계에서 동일한 `runId`로 자동 재개됩니다. 이 전환 시 `runId`, 전체 `task`, 이전 단계 완료 결과(`earlierStageOutputs`), 실패 단계의 현재 부분 답변(`currentPartial`), 해당 단계 역할(`stageRole`), 남은 단계 구성(`laterStages`)이 모두 보존됩니다. 카운트다운 중 사용자는 후보 선택(`select`), 건너뛰기(`skip`), 취소(`cancel`)가 가능하며 메인 창 포커스를 잃으면 카운트다운이 일시정지됩니다. 후보 자리는 설정된 자리일 뿐 실제 로그인 여부나 쿼터가 검증된 것이 아닙니다. 알 수 없는 오류나 인증 실패 시에는 자동으로 넘어가지 않고 즉시 멈추며 재시도 루프를 돌지 않습니다. 기존의 명시적 수동 이어받기(사용자의 명시적 공유 확인 및 대상 v2 동의 필요)도 유지됩니다. 웹과 3단계 릴레이 간의 자동 핸드오프는 지원하지 않으며(3단계 릴레이는 동일 제공자 CLI 간으로만 한정), 앱 시작이나 새로고침 시 자동 재개되지 않습니다. 릴레이 자체는 브라우저 조작이나 로그인 자동화를 포함하지 않습니다.
- **세 단계는 세 계정이 아니라 세 번의 CLI 실행입니다.** 기본 계정은 이 PC의 공용 CLI 로그인 계정이며(초기 실행에는 별도 자리 선택자를 두지 않음), 같은 서비스를 두 단계에 쓰면 같은 계정을 두 번 사용합니다. 쿼터 소진 시에만 준비된 동일 제공자 독립 자리로 5초 자동 이어받기 또는 명시적 수동 전환을 수행할 수 있습니다. 팀원별 임의 자동 계정 교체나 사용량 제한 우회를 하지 않으며 제한에 걸리면 멈춥니다. 앱은 API 키를 묻거나 저장하지 않습니다.
- **자동 실행의 환경 설정을 제한합니다.** 공용 Claude·Codex도 독립 자리와 같은 환경 변수 허용 목록을 사용하여 부모 프로세스의 API 키·접속 주소 변경·Node 사전 로딩 설정을 전달하지 않습니다. 기존 OS 사용자 폴더와 해당 서비스에 명시된 로그인 설정 폴더는 유지합니다. 별도로 여는 수동 터미널은 기존 사용자 환경을 사용합니다.
- **텍스트·코드 제안만 받습니다. 차단 방식은 공급자마다 다릅니다.**
  - Claude Code: `-p --output-format stream-json --verbose --include-partial-messages --safe-mode --tools "" --strict-mcp-config --permission-mode dontAsk --permission-prompts none --no-session-persistence --disable-slash-commands`. `--safe-mode`가 훅·MCP·플러그인·스킬·CLAUDE.md 등 사용자 설정을 끄고, `--tools ""`로 내장 도구가 없으며, 권한 요청은 자동 거부됩니다. 관리자 정책(managed settings)은 CLI가 계속 적용합니다.
  - Codex CLI: `exec --json --sandbox read-only --ignore-user-config --ignore-rules -c approval_policy="never" -c mcp_servers={} --ephemeral --skip-git-repo-check --cd <workspace> -`. 사용자 `config.toml`(MCP 서버·훅·프로필 포함)과 규칙 파일을 읽지 않고 승인 요청 없이 읽기 전용 샌드박스에서 실행합니다. **읽기 전용 샌드박스는 파일 수정을 막지만 읽기 전용 명령 실행까지 막지는 않습니다.** 명령 실행·파일 변경·MCP 호출 이벤트가 오면 그 단계를 중단하지만, 이는 사후 감지이며 짧은 읽기 전용 명령은 이미 실행됐을 수 있습니다.
  - Gemini CLI: 소스 확인한 `0.59.0`으로 고정합니다. 앱 전용 `GEMINI_CLI_HOME`과 정책 파일에서 `tools.core=[]`, `hooksConfig.enabled=false`, skills 비활성화를 적용하고 `--extensions none`과 미등록 임의 이름의 MCP 허용 목록으로 실행합니다. 기존 관리자 설정이 감지되면 덮어쓰지 않고 중단합니다. 사용자 질문은 JSON으로 전달하고 `@`를 Unicode 이스케이프해 CLI의 파일 첨부 전처리를 막습니다. 기존 개인 Gemini 설정·인증은 읽거나 복사하지 않습니다.
  - 릴레이는 시작 전에 설치된 CLI의 `--help`(모델 요청 없음)에서 위 옵션이 모두 있는지 확인하고, 하나라도 없으면 요청을 보내지 않고 옵션 이름과 함께 멈춥니다. 더 약한 옵션으로 대체하지 않습니다. Claude/Codex 작업 폴더는 `Data/Relay/workspace`(대화는 `Data/Chat/workspace`), Gemini는 PC의 앱 전용 로그인 폴더 아래 `workspace`입니다.
- 화면에는 CLI가 보낸 답변 본문과 단계 상태(대기·연결·답변 받는 중·저장·완료·오류·중지·중단), 실제 경과 시간만 표시합니다. 내부 사고 과정, 진행률 추정, 로그인 정보, 오류의 원문 stderr는 표시하거나 저장하지 않습니다.
- 단계마다 10분 제한, 답변 20만 자 제한, 단계 입력 15만 자 제한, 실행 1회당 저장 3MB 제한이 있습니다. 넘으면 잘라내지 않고 오류로 멈추며 화면의 부분 답변은 단계별 "이 단계 복사"로 가져갈 수 있습니다. 자동 재시도는 없으며 다시 보내려면 직접 시작을 눌러야 합니다.
- **중지**는 언제나 누를 수 있고 앱이 만든 CLI 프로세스 그룹(하위 프로세스 포함)만 종료합니다. 완료된 단계와 받던 부분 답변은 화면에 남고 저장에 성공한 범위까지 보관함에 남습니다. 앱을 닫을 때는 진행 중 릴레이를 먼저 중지하고 프로세스가 실제로 끝난 뒤에만 보관함을 잠급니다. 프로세스가 끝나지 않으면 앱을 닫지 않고 오류를 표시합니다. 다시 열면 이전 실행은 "중단됨"으로 표시되며 자동으로 이어 달리지 않습니다.
- 릴레이 기록은 최대 20개까지 `Data/team.vault`의 별도 필드에 암호화 저장됩니다. 기록이 20개이거나 보관함 여유(25MB 상한 대비 3MB)가 부족하면 새 릴레이를 시작하지 않으며, 오래된 기록을 자동으로 지우지 않습니다. 기록 삭제는 "이전 릴레이 기록" 목록에서 직접 합니다. 시작하지 않은 작업·역할 초안은 저장되지 않습니다. 0.3 보관함과 기록은 그대로 읽습니다.
- Claude/Codex는 공식 CLI의 로그인을 먼저 마치세요. Gemini는 첫 질문 시 공식 Google 로그인창이 열릴 수 있습니다. 브라우저 로그인을 지원하지 않는 환경에서는 로그인 터미널을 이용하세요. Windows에서는 npm CLI를 Node.js로 직접 실행하며 셸을 거치지 않습니다.

## CLI 1:1 대화 (앱 내 실행)

- **사용 방법**: 실행 준비에서 설치 상태를 확인하고, 필요한 경우 로그인 터미널에서 로그인한 뒤 **CLI 대화**를 누릅니다. 질문 입력 → 전송 → 앱 안에서 답변 확인 → 이어 질문하기 순서로 사용합니다. 중지와 답변 복사, 이전 기록 보기·삭제도 제공합니다.
- **지원 범위**: 호환되는 Claude Code·Codex CLI·Gemini CLI를 앱 대화창에 연결합니다. CLI가 텍스트를 보내는 시점에 화면이 갱신되므로 서비스마다 답변 표시 속도가 다릅니다. 웹 화면과 CLI 화면은 오갈 수 있지만 웹 대화를 CLI 대화로 자동 동기화하지는 않습니다.
- **맥락 유지**: 매 전송은 단일 실행(1 stage)으로 완료되며, 연속 대화는 앱이 이전 질문/답변 턴을 조합하여 task에 포함(최대 50,000자, 자동 절단 없음)해 전달합니다. 공급자를 바꾸거나 새 대화를 시작하면 이전 맥락은 명시적 확인 후 초기화됩니다.
- **계정 및 인증**: CLI 대화는 이 PC의 공용 CLI 계정 또는 팀원별 독립 CLI 자리로 실행됩니다. 공용 CLI의 인증 정보는 PC 로컬에 남아 USB 보관함으로 이동하지 않습니다. 독립 CLI 자리는 명시적인 ‘로그인 보관’·‘로그인 복원’·‘보관된 로그인 삭제’ 제어를 통해 비밀번호로 암호화된 `Data/team.vault`에 공식 CLI 토큰(Codex `auth.json`, Gemini `.gemini/oauth_creds.json`, Claude Windows/Linux `config/.credentials.json`)을 안전하게 보관하고 빈 자리에 복원할 수 있습니다. Mac Claude Keychain 이동은 지원되지 않으며 전역 키체인이나 타 앱 비밀정보는 가져오지 않습니다. 복원된 파일은 PC 로컬의 공식 CLI 평문 저장소이므로 앱 보관함 암호화가 PC 사본을 보호하지 않으며, 토큰 만료/회전 시 공식 로그인이 다시 필요할 수 있습니다. 앱은 로그인 비밀번호나 API 키를 묻지 않습니다.
- **저장**: 각 전송의 입력과 결과는 `Data/team.vault`에 암호화 저장됩니다. 이전 기록은 당시 조합한 입력과 답변으로 표시합니다. 전송 전 대화창 초안은 저장되지 않습니다. CLI 자체 인증·설정·기록은 해당 도구가 관리하며 앱 보관함과 별개입니다.

## 처음 시작하기

1. Windows x64 ZIP **전체**를 쓰기 가능한 USB 폴더에 풀고 AIplaygrand-Win.exe를 실행합니다. exe만 옮기면 실행되지 않습니다.
2. 팀 보관함 비밀번호를 설정합니다. 빈 값과 공백을 포함해 길이·문자 조합 규칙은 없으며, 잊으면 복구할 수 없으니 안전한 비밀번호 관리자에 별도 보관하세요.
3. 기본 팀원의 **열기**에서 각자 공식 웹사이트에 로그인합니다. 앱은 서비스 비밀번호를 수집하지 않습니다.
4. 질문을 적고 **웹 브라우저 / CLI 대화(앱 안에서) / CLI 터미널**을 선택해 미션을 추가합니다. 웹 팀원 선택으로 CLI 로그인 계정이 바뀌지는 않습니다.
5. 웹과 터미널은 질문을 복사한 뒤 직접 붙여 넣어 전송합니다. 앱 내 CLI 대화는 입력창에 미션을 넣어 주며 **전송**을 눌러야 시작합니다. 답변을 보면서 추가 질문을 할 수 있습니다.
6. **저장하고 종료**, 별도로 연 **CLI 터미널 종료**, Windows의 **하드웨어 안전하게 제거** 순서로 마칩니다.
7. 다른 PC에서 같은 앱을 열고 보관함 비밀번호를 입력합니다. 서비스나 CLI 로그인은 다시 필요할 수 있습니다.

## 저장과 암호화 범위

앱 웹창은 카메라·마이크·위치·알림 등 사이트 권한 요청을 기본 거부합니다. 텍스트 학습용이며 음성·위치 기능은 지원하지 않습니다. 사이트의 클립보드 API가 동작하지 않으면 글을 선택해 키보드로 복사·붙여넣으세요.

| 항목 | 위치와 보호 범위 |
| --- | --- |
| 팀원·질문 초안·미션·답변·앱 웹창 쿠키·독립 CLI 자리 보관 로그인(선택)·CLI 릴레이/대화 기록 | Data/team.vault 암호화 보관함 (비밀번호 보호) |
| CLI 릴레이 작업 폴더 | Data/Relay/workspace 빈 폴더 |
| 직전 보관함 | Data/team.vault.bak 역시 암호화 (삭제된 로그인 사본이 남을 수 있음) |
| CLI 설치 패키지 | Data/Tools/운영체제-CPU/ 일반 파일 |
| CLI 작업 시작 폴더 | Data/Projects/ 일반 파일 |
| 다운로드·내보낸 JSON | 일반 파일, 암호화되지 않음 |
| 공용 CLI 인증 및 PC 복원된 독립 자리 로컬 파일 | 각 공식 도구가 PC에서 관리 (OS 권한 평문 파일, 앱 암호화 미보호) |
| 이전 버전 JSON·브라우저 데이터 | 기존 파일 보존. 자동 삭제·암호화되지 않음 |

보관함은 scrypt와 AES-256-GCM으로 보호합니다. 실행 중 복호화된 내용은 메모리에 있습니다. 악성코드가 있는 PC, 화면 녹화, 운영체제 임시 기록까지 보호하는 무흔적 실행은 아닙니다. 보관함 비밀번호를 아는 사람은 팀 전체 기록과 저장된 세션을 사용할 수 있으므로 신뢰하는 팀에서만 공유하세요.

## 로그인 이동의 범위

앱 안에서 직접 로그인한 Claude·Gemini·Codex 웹 세션의 쿠키를 암호화하고 다음 실행에서 복원을 시도합니다(쿠키 복원은 최선 노력/best-effort). 다른 브라우저의 인증정보를 가져오지 않습니다. 쿠키 복원 성공은 로그인 성공이 아닙니다. LocalStorage, IndexedDB, 기기에 묶인 인증 키는 이동하지 않습니다. 독립 CLI 자리의 보관 대상 파일(Codex auth.json, Gemini oauth_creds.json, Claude Windows/Linux config/.credentials.json) 외의 전역 키체인이나 공용 CLI 인증은 보관함으로 이동하지 않습니다. 만료되거나 기기 인증이 필요한 세션은 공식 화면에서 다시 로그인해야 합니다. 실제 계정의 PC 간 로그인 유지 여부는 아직 검증되지 않았습니다.

각 웹 팀원은 별도 브라우저 세션을 사용합니다. **기본 공용 CLI는 팀원별 계정 격리가 아닙니다.** 해당 PC에서 공식 CLI에 로그인한 계정 하나를 사용하므로 계정을 직접 확인하세요. 팀원별 격리가 필요하면 ‘독립 CLI 자리’를 추가하세요. 웹 팀원 선택만으로 공용 CLI 계정이 바뀌지 않습니다.

## CLI 설치 도움

실행 시 Node.js·npm·Git·Claude Code·Gemini CLI·Codex CLI의 설치와 버전을 점검합니다. 메모리와 USB 여유 공간도 표시합니다. 인터넷 연결과 계정 이용권은 보장하지 않습니다.

- 웹 모드는 Node.js나 CLI 추가 설치 없이 사용할 수 있습니다.
- CLI 설치에는 Node.js 20 이상과 npm이 필요합니다. 없으면 **공식 설치 안내**에서 설치하고 **다시 점검**하세요. Git은 권장 도구이며 필수 여부는 도구별로 다릅니다.
- **USB에 설치**는 확인 후 터미널에서 공식 npm 패키지를 USB의 Tools 아래에 설치합니다. 관리자 권한이나 전역 설치를 자동으로 요구하지 않습니다. 끝난 뒤 다시 점검해야 성공 여부가 확인됩니다.
- **CLI 열기**는 터미널을 여는 기능입니다. 자동 로그인·질문 전송·응답 수집을 하지 않습니다. Claude 무료 웹 계정에는 Claude Code 이용권이 포함되지 않습니다.
- PC의 Node.js와 공용 CLI 인증은 USB만으로 이동하지 않습니다(독립 CLI 자리는 명시적 보관/복원 기능 제공). 운영체제/CPU가 달라지면 맞는 도구를 준비해야 합니다. 별도 터미널은 앱 종료 후에도 남을 수 있습니다.

이 앱의 '웹'은 공식 AI 웹사이트 실행 모드이며 독립 웹사이트 제품이 아닙니다. 일반 웹사이트만으로 다른 사이트의 로그인 쿠키를 읽거나 PC의 CLI를 실행할 수 없습니다.

## 저장 실패·백업·업데이트

정상 저장 시 직전 파일을 .bak로 보존하고 새 파일로 교체합니다. USB 쓰기 실패 시 오류를 표시합니다. 빈 기록으로 덮어쓰거나 PC 폴더로 몰래 전환하지 않습니다. USB를 연결하고 다시 저장하세요. 강제 종료·전원 차단·작업 중 USB 분리는 최근 입력 손실과 파일 손상을 일으킬 수 있습니다. 기록 내보내기 시 기존 파일은 .bak 백업으로 남깁니다. 내보낸 JSON과 백업을 별도로 암호화하지 않으므로 보관 위치에 주의하세요.

장치 분실·고장에 대비해 **종료 후 전체 폴더를 별도 저장소에 복사**하세요. 복구는 앱을 닫고 Data 전체를 먼저 복사한 뒤, 손상 원본을 별도 이름으로 보존하고 정상적인 team.vault.bak 복사본을 team.vault로 배치합니다. 백업에도 같은 비밀번호가 필요합니다.

0.2 기록은 첫 보관함 생성 시 복사됩니다. 원래 JSON과 Browser 파일은 그대로 남으므로 완전한 보호가 필요하면 새로운 폴더에서 시작하세요. 기존 파일은 임의로 삭제하지 않습니다. 0.1 기록은 이전 버전의 JSON 내보내기로 옮깁니다.

### Windows x64 휴대용 동의형 자체 업데이트 (실기기 미검증)

- **처음 한 번은 직접 교체합니다.** 지금 배포된 0.5.0 패키지에는 업데이터가 없습니다. 자체 업데이트가 들어간 첫 버전은 0.6.0으로, 이 버전은 GitHub에서 ZIP을 내려받아 기존 폴더의 프로그램 파일을 직접 바꿔 넣어야 하며, 그다음 버전부터 앱 안에서 업데이트할 수 있습니다. Windows x64 패키지 전용이며 macOS·개발 실행에서는 네트워크 요청 없이 '미지원'으로 표시됩니다. 이 기능은 아직 실제 Windows·USB에서 실행해 보지 않았습니다.
- **확인과 동의.** 앱을 시작할 때 한 번(보관함 잠금 화면에서도) 그리고 상단 또는 잠금 창의 '업데이트 확인' 버튼으로 GitHub 릴리스 목록을 읽습니다. 새 버전이 있으면 '나중에(기본값)'와 '지금 업데이트'를 묻고, 동의 전에는 아무것도 내려받지 않습니다. GitHub에서 시험 배포(prerelease)로 표시된 릴리스는 안내 문구와 함께 허용합니다.
- **다운로드와 검증.** 주소는 `https://github.com/armsone/AIplaygrand-Win/releases/download/v<버전>/AIplaygrand-Win-<버전>-x64.zip`으로 고정되어 있고, 크기와 SHA-256은 GitHub API가 자산에 붙이는 `digest` 값만 사용합니다(릴리스 본문의 문자열은 쓰지 않음). 값이 없으면 설치하지 않습니다. 파일은 실행 파일 옆 `.aiplaygrand-update\<UUID>\`에 스트리밍으로 받으며 크기가 다르거나 해시가 다르면 버립니다. 이 검증은 '공식 GitHub HTTPS에서 받은 그 바이트'임을 확인하는 것이지 Authenticode 코드 서명 검증이 아닙니다.
- **준비 단계와 승인.** 다운로드가 끝나면 Windows PowerShell 5.1 도우미(`apply-update.ps1`, 스테이지 폴더로 복사됨)가 ZIP 항목을 고정 허용 목록(실행 파일, Electron 런타임 파일, `locales\*.pak`, `resources\app.asar`, 안내 문서)과 대조하고 링크 항목·경로 조작을 거부한 뒤 `extracted\`에 풀어 해시를 저널에 기록하고 '준비 완료' 신호를 보냅니다. 도우미가 시작되지 않거나 검사에 실패하면 앱은 그대로 열린 채 오류만 표시합니다. 준비가 끝났을 때 진행 중인 작업(CLI 대화·릴레이·웹 자동 전송·자동 이어받기·미저장 결과·자격 증명 확인)이 없으면 평소의 '저장하고 종료'를 자동으로 실행하고, 작업 중이면 끊지 않고 '업데이트 적용' 버튼으로 바뀌어 확인 뒤 직접 적용합니다. 보관함·쿠키·기록 저장이 모두 성공한 다음에만 승인 마커를 쓰고, 도우미는 승인 마커와 앱 프로세스의 실제 종료를 둘 다 확인한 뒤에야 파일을 건드립니다. 종료가 취소되거나 저장이 실패하면 승인은 취소되고 준비된 파일은 버려지므로, 이후의 평범한 종료에서 몰래 적용되지 않습니다.
- **교체 트랜잭션.** 도우미는 원본을 `backup\`으로 옮기고 새 파일을 제자리로 옮긴 뒤 설치된 파일의 해시를 다시 확인하고 나서야 앱을 다시 시작합니다. 각 단계는 저널(`update-journal.json`, 임시 파일 작성·디스크 반영 후 이름 변경)에 기록되며, 파일을 하나 옮기기 전에 '옮기려 함' 단계를 먼저 쓰고 옮긴 뒤에 '옮김' 단계를 씁니다. 실패하면 저널을 따라 되돌리되 저널의 단계 표시만 믿지 않고, 항목마다 제자리 파일과 `backup\` 파일의 실제 해시를 원본·새 파일 해시와 대조해 판정합니다(옮긴 직후 단계를 쓰기 전에 전원이 끊긴 경우도 포함). 마지막에 모든 항목이 원본 상태(원본 해시 일치, 또는 원래 없던 파일이 없음)인지 다시 검증한 뒤에만 '되돌림(`rolled_back`)'으로 보고하고 이전 버전을 다시 실행하며, 섞인 상태(`mixed`)에서는 다시 실행하지 않고 안내만 띄웁니다. `Data\`, `Tools\`, 사용자가 둔 파일은 어떤 경우에도 옮기거나 지우지 않습니다. 새 파일을 되돌릴 때도 지우지 않고 `failed\`로 옮기며, `backup\`은 어떤 결과에서도 지우지 않습니다.
- **전원·USB 분리 시.** 교체 도중 전원이 꺼지거나 USB가 빠지면 다음 실행에서 복구 안내가 표시됩니다. 앱을 닫고 해당 스테이지 폴더에서 다음을 실행하면 저널을 바탕으로 되돌리기를 다시 시도합니다(멱등, 실행 중인 앱이 있으면 기다림). 저널 항목의 경로·해시·단계 값이 이상하거나 중복이거나 대상 자리에 폴더·링크가 있으면 파일을 옮기기 전에 중단하고 `rollback_failed`로 보고합니다:

  ```
  powershell -NoProfile -File "<앱 폴더>\.aiplaygrand-update\<UUID>\apply-update.ps1" -Action Recover -StageDir "<앱 폴더>\.aiplaygrand-update\<UUID>" -AppDir "<앱 폴더>"
  ```

  FAT/exFAT USB와 갑작스러운 전원 차단에서는 이 절차도 완전한 복구를 보장하지 못하므로, 업데이트 전 폴더 전체를 다른 곳에 복사해 두는 것을 권장합니다.
- **알아 둘 점.** 업데이트가 끝나 앱이 다시 열릴 때까지 USB를 빼지 마세요. 원본 백업과 준비 파일은 `.aiplaygrand-update\` 아래에 남아 USB 공간을 차지하며 앱이 자동으로 지우지 않습니다(정상 동작을 확인한 뒤 직접 지우세요). 도우미는 관리자 권한 요청, 실행 정책 변경, `-ExecutionPolicy Bypass`를 쓰지 않습니다. PC의 PowerShell 실행 정책이 `Restricted`나 `AllSigned`이면 앱은 그 사실을 표시하고 기존 버전을 그대로 둡니다. 도우미에는 Windows PowerShell 5.1과 .NET Framework 4.7.2 이상이 필요합니다(ZIP 항목의 링크 속성 검사에 `ZipArchiveEntry.ExternalAttributes`를 씁니다). 더 오래된 .NET에서는 검사를 건너뛰지 않고 준비 단계에서 중단하며 오류 문구로 안내합니다. 그런 PC에서는 ZIP을 직접 내려받아 교체하세요. 다운로드·준비 중 '취소'는 명시적인 취소 표시로 처리되어 파일 핸들이 닫힌 뒤 스테이지를 정리하고, 앱 폴더 검사·여유 공간·스테이지 생성처럼 다운로드 전에 실패한 경우도 취소로 오인하지 않고 오류를 표시합니다.

서비스별 이용 연령·계정 이용권을 지켜 사용하세요. 미성년자에게 성인용 계정을 공유하지 말고 서비스가 허용하는 보호자 관리 방식을 확인하세요. AI 답변은 팀이 함께 검토합니다.

## 개발과 검증

npm ci, npm start로 Mac에서 개발 실행합니다. node --test tests/*.test.js로 저장·암호화·실패 보존·화면 로직을 검사하고 npm run dist:win으로 Windows x64 ZIP을 만듭니다. 개발도 프로젝트 옆 Data에 저장하므로 실제 기록 대신 격리된 테스트 폴더를 쓰세요. Data·테스트·개인 기록은 패키지에서 제외합니다.

Mac 테스트와 Windows 패키징은 Windows 실기기 검증을 대신하지 않습니다. Windows 실행·설치 도우미·물리 USB 분리·실제 계정의 PC 간 로그인 복원, Windows에서의 CLI 릴레이 실행(npm 심(shim) 해석·taskkill 종료)은 별도 확인이 필요합니다. Windows에서는 CLI 본 프로세스가 먼저 끝나고 하위 프로세스만 남은 경우 앱이 그 하위 프로세스를 종료할 수단이 없어 해당 단계를 실패로 표시합니다. 릴레이는 각 CLI의 공식 비대화형 스트리밍 JSON 출력(`claude -p --output-format stream-json`, `codex exec --json -`)을 읽으며, CLI 버전이 바뀌어 출력 형식이 달라지면 완료로 인정하지 않고 오류로 표시합니다. 이 문서의 릴레이 설명은 구현 내용이며 실제 모델 요청으로 검증한 결과가 아닙니다.
